Patrón MVT y Ciclo de Vida de una Petición en Django

Django implementa una variación del clásico patrón MVC (Model-View-Controller) llamada MVT (Model-View-Template).

🔄 Ciclo de Vida: De la URL a la Pantalla

1
Navegador (Request)
El usuario visita /manual/ en su navegador emitiendo una petición HTTP GET.
→
2
Middlewares
Capas de seguridad, sesión y autenticación procesan la petición antes de enrutarla.
→
3
URL Resolver (urls.py)
Compara la ruta solicitada con los patrones de URLs y deriva a la vista correspondiente.
→
4
Vista (views.py)
Ejecuta la lógica de negocio, consulta el Modelo (ORM) y prepara el contexto.
→
5
Template (HTML)
El motor DTL renderiza el HTML combinando variables de contexto y responde con HTTP 200.
M

Modelo (models.py)

Capa de Datos y Persistencia (ORM).

Define las tablas de la base de datos usando clases de Python. Django traduce automáticamente las consultas de Python (ej. Mensaje.objects.filter(activo=True)) a sentencias SQL seguras contra inyección SQL.

Archivo: apps/*/models.py
V

Vista (views.py)

Capa de Lógica y Control.

Es la función o clase que procesa el request, aplica reglas de negocio, valida formularios, interactúa con el Modelo y decide qué respuesta devolver (HTML, JSON o Redirección).

Archivo: apps/*/views.py
T

Template (.html)

Capa de Presentación e Interfaz de Usuario.

Archivos HTML enriquecidos con el lenguaje de plantillas de Django (DTL). Permite herencia de plantillas ({% verbatim %}{% extends "base.html" %}{% endverbatim %}), bucles ({% verbatim %}{% for item in lista %}{% endverbatim %}) e inserción de variables ({% verbatim %}{{ variable }}{% endverbatim %}).

Archivo: templates/*.html

🧩 ¿Por qué organizamos el código en apps/?

Una App en Django es un paquete autónomo que resuelve un dominio funcional específico (por ejemplo: apps/core, apps/manual, apps/usuarios, apps/datos, apps/ia).

  • Desacoplamiento: Cada app contiene sus propios modelos, vistas, urls, formularios y tests.
  • Mantenibilidad: Si necesitas remover una funcionalidad o cambiar su comportamiento, podés hacerlo sin afectar al resto del sistema.
  • Reutilización: Podés exportar una app a otro proyecto Django con mínimo esfuerzo.
